## Goal
Seed realistic GTM fixture data into the 4 new GTM databases so every downstream worker has live rows to read during development and the live demo.

## Why this exists
The GTM pipeline workers (PRD-15, PRD-16, PRD-18) need existing data to demonstrate meaningful output. Without pre-seeded meeting notes and opportunities, the Release Bridge cannot flag any deals, the Daily Summarizer has nothing to summarize, and the Battle Card Updater has no competitive intel to update. The fixtures also tell the demo story: two enterprise deals are in flight, a key product just shipped, and a rep hasn't heard about it yet.

### `scripts/seed-gtm-fixtures.ts`

- Upserts by `Title` (skip if title already exists in the DB).
- Creates Opportunity rows first (no dependencies), then Meeting Notes rows (need Opportunity page IDs for the relation).
- Uses `NOTION_IDS.dbs.opportunities`, `NOTION_IDS.dbs.gtmMeetingNotes`, etc. from `src/lib/notion-ids.ts`.
- Relation between Meeting Notes and Opportunities: set by looking up the just-created Opportunity page ID by title.
- Relation between Opportunities and PRDs: use hardcoded PRD IDs from PRD-01 Implementation Notes.
- Logs each created row with its title and page ID.
- `--dry-run` flag: print what would be created without calling the API.

## Implementation Notes

> Written post-build. Read this section before building any PRD that depends on this one.

### What was actually built

- **`scripts/seed-gtm-fixtures.ts`**: New idempotent seed script. Runs in 4 sequential steps: Opportunities → Meeting Notes → Battle Cards → Daily Digest. Step ordering is load-bearing — Meeting Notes carry a `relation` property back to Opportunity page IDs, so Opportunities must be created first and their IDs collected into an in-memory map before step 2 runs. The `upsertRow()` helper always queries Notion even in `--dry-run` mode, so dry-run skip counts reflect reality rather than always printing "would create." Final totals: 8 opportunities, 17 meeting notes (W19–W23), 3 battle cards, 4 daily digest stubs (W19–W22; W23 generated live by PRD-15 worker).
- **`scripts/reset-data.ts`**: Extended with a new `"date-range"` strategy (parameterized via `dateProperty` on `DbEntry`) for filtering GTM DBs by their plain `Date` field. Added a `GTM_DB_IDS` Set that contains only the two *weekly* GTM DBs (Daily Digest + Meeting Notes) — Opportunities and Battle Cards are deliberately excluded since they are persistent records. Added a `--scope=eng|gtm` CLI flag that filters `DATA_DBS` against this Set.
- **`package.json`**: Added `"seed-gtm-fixtures": "tsx --env-file=.env.local scripts/seed-gtm-fixtures.ts"` alias per project convention.

### Gotchas for downstream sessions

**1. `ntn api ... | jq` parse error — use `-X POST` and `python3` for DB queries**
The `ntn api v1/databases/{id}/query` command requires an explicit `-X POST` flag to return JSON; without it the CLI emits non-JSON output that `jq` cannot parse (exit code 5, "Invalid numeric literal"). Replace with:
```bash
ntn api v1/databases/{id}/query --notion-version 2022-06-28 -X POST \
  | python3 -c "import sys,json; d=json.load(sys.stdin); print(len(d['results']))"
```

**2. PRD status block drifted to `waiting` after PRD-13 approval**
When PRD-13 was approved, the README row was updated to `ready` but the `<!-- status: -->` block inside this PRD file was never patched. The README is authoritative per SOP; the block was corrected to `in-progress` at claim time. Future sessions: if a PRD file's status block disagrees with the README, always trust the README and update the file to match.

**3. Rep names in fixtures differ from schema select options**
`patch-schema-round2.ts` seeded the `Rep` select options with placeholder names ("Alice Mercer", "Ben Torres", etc.). The fixture data uses the PRD-specified names ("Sarah Chen", "Marcus Webb", "Jordan Park"). Notion creates new select options on the fly when a page is created with an unknown option value, so this works — but the DB's select option list now has two sets of names. This is cosmetic; it has no functional impact on downstream workers.
