# PRD-06 — Per-Squad HITL Review

## Goal
Give each squad's EM a single Notion page that consolidates all 6 of that squad's weekly summaries with one Approve action, replacing the 18-click world from `solution-intro.md`.

## Why this exists
HITL only works if the friction is bearable. Per-squad consolidated review is the simplest model that still gives a human accountability per squad. It's also the thing that, post-POC, decays gracefully — start opt-in HITL on, opt out over time.

## Dependencies
- PRD-00, PRD-01. Can be designed in parallel with PRD-04 — only the data shape matters, not its content.

## Inputs
- The 6 Squad Weekly Summary rows for one squad × one week.

## Outputs
- A **templated Notion page** under each Squad page: "Week of YYYY-MM-DD — Review."
- The page embeds (linked database view, or inline Notion blocks pulling content via the API) all 6 summaries with their citations expanded.
- A single **Approve** button (Notion button block) that sets `Status = approved` on all 6 summaries atomically, and writes a row to Agent Run Log tagged `approval.squad.<squad>`.
- A **Reject + comment** flow that sets `Status = rejected` on selected sub-summaries and emails/pings the responsible agent for re-run.

## Design
- Page generated by an agent triggered on completion of all of a squad's per-source + product summaries (PRD-04a + 04b done).
- Approve button executes a Notion automation (or a Worker endpoint called by a button) — implementing session decides the cleaner path.
- Reject flow: per-sub-summary checkbox. Rejected ones go back to their summarizer for a single re-run with the rejection comment as context, then resurface here.
- Approval state is what the Master Summarizer (PRD-05) watches for.

## Acceptance Criteria
1. Per-week, per-squad review page exists with all 6 sub-summaries visibly embedded.
2. Approve button changes all 6 sub-summary statuses to `approved` in one click.
3. Reject flow on 1 of 6 leaves the other 5 untouched and signals re-run.
4. Re-run completes and the re-generated sub-summary reappears in the review page automatically.

## Out of Scope
- Per-sub-summary editorial editing UI — too much for V1. EMs reject and let the agent re-try; if quality is unfixable, they fall back to manual writing for the week.
- Slack / email notifications beyond a Notion-native mention — V2.

## Open Questions
- Notion button → Worker endpoint auth model. Implementing session probes Notion's native automation capabilities and falls back to a server endpoint if needed.

## Verification
- Demo: open Atlas → Week of <W> Review. See 6 embedded summaries. Click Approve. Open Squad Weekly Summary DB filtered to Atlas + that week — all 6 say `approved`.
